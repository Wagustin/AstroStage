## 2024-06-29 - Email HTML Injection & Info Leakage
**Vulnerability:** The API endpoint `api/subscribe.ts` was vulnerable to HTML Injection because it embedded the user-provided `email` directly into the HTML of the outgoing email without escaping. Additionally, it leaked internal server error messages to the client and trusted the `Host` header for generating the logo URL (Host Header Injection).
**Learning:** Even when sending emails, user input must be sanitized. Email clients render HTML, making them susceptible to injection attacks. Trusting user-provided headers like `Host` can lead to SSRF or phishing vectors in emails. Finally, exposing `error.message` to the client violates the "fail securely" principle.
**Prevention:** Always escape user input before embedding it in HTML. Never trust the `Host` header for constructing URLs sent in emails. Generic error messages should be returned for 500 errors.

## 2026-07-17 - Unhandled Exception & Server Configuration Leakage
**Vulnerability:** The API endpoint `api/subscribe.ts` was blindly destructuring `req.body` and passing `req.body.email` directly to string methods (`.includes()`). It also leaked server configuration details ("Falta configurar RESEND_API_KEY en Vercel.") when the Resend API key was missing.
**Learning:** Vercel serverless function endpoints receive raw request objects. Not validating `req.body` type and existence causes `TypeError` which can lead to Denial of Service (DoS) by crashing the endpoint. Error messages should fail securely and never expose internal infrastructure or configuration requirements.
**Prevention:** Always validate `req.body` is a valid object before destructuring. Check the type of extracted variables (`typeof email === 'string'`) before using object-specific methods. Return generic error messages for server misconfigurations (500 errors).
