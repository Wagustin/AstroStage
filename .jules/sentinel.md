## 2024-06-29 - Email HTML Injection & Info Leakage
**Vulnerability:** The API endpoint `api/subscribe.ts` was vulnerable to HTML Injection because it embedded the user-provided `email` directly into the HTML of the outgoing email without escaping. Additionally, it leaked internal server error messages to the client and trusted the `Host` header for generating the logo URL (Host Header Injection).
**Learning:** Even when sending emails, user input must be sanitized. Email clients render HTML, making them susceptible to injection attacks. Trusting user-provided headers like `Host` can lead to SSRF or phishing vectors in emails. Finally, exposing `error.message` to the client violates the "fail securely" principle.
**Prevention:** Always escape user input before embedding it in HTML. Never trust the `Host` header for constructing URLs sent in emails. Generic error messages should be returned for 500 errors.
## 2026-08-03 - Unhandled TypeError Server Crash Vulnerability
**Vulnerability:** The Vercel API endpoint `api/subscribe.ts` did not properly validate the existence and type of `req.body` and `req.body.email` before destructuring and calling string methods. Sending malformed requests (e.g., missing body, or array instead of string) could cause unhandled TypeError exceptions, leading to potential Denial of Service (DoS) conditions through server crashes.
**Learning:** Vercel serverless functions receive raw request bodies. Destructuring directly from `req.body` or calling methods like `.includes()` on user-supplied variables without explicit type checking is dangerous and can lead to 500 Server Errors.
**Prevention:** Always validate that `req.body` exists and is an object before destructuring. Explicitly check that destructured fields have the expected type (e.g., `typeof email === 'string'`) before calling type-specific methods.
