## 2024-07-15 - Unhandled TypeError from Missing Validation on Vercel Raw Requests
**Vulnerability:** The API endpoint `api/subscribe.ts` directly destructured `req.body` without validating its existence or type. Vercel API endpoints can receive raw request objects where `req.body` might be undefined or not an object. This can lead to unhandled TypeErrors (Server Crash / 500 error), potentially allowing for Denial of Service via malformed requests. Furthermore, `email` length was not validated.
**Learning:** Always validate the structure and presence of expected data from incoming requests, especially in environments like Vercel where raw request objects are passed directly to handlers. Missing validation on input types and existence can lead to server crashes. Missing length validation can lead to resource exhaustion.
**Prevention:** Implement explicit checks to ensure `req.body` exists and is an object before destructuring. Validate specific fields like `email` for type, existence, and reasonable length limits (e.g., max 254 characters) before processing.

## 2024-06-29 - Email HTML Injection & Info Leakage
**Vulnerability:** The API endpoint `api/subscribe.ts` was vulnerable to HTML Injection because it embedded the user-provided `email` directly into the HTML of the outgoing email without escaping. Additionally, it leaked internal server error messages to the client and trusted the `Host` header for generating the logo URL (Host Header Injection).
**Learning:** Even when sending emails, user input must be sanitized. Email clients render HTML, making them susceptible to injection attacks. Trusting user-provided headers like `Host` can lead to SSRF or phishing vectors in emails. Finally, exposing `error.message` to the client violates the "fail securely" principle.
**Prevention:** Always escape user input before embedding it in HTML. Never trust the `Host` header for constructing URLs sent in emails. Generic error messages should be returned for 500 errors.
