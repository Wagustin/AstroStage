## 2024-06-29 - Email HTML Injection & Info Leakage
**Vulnerability:** The API endpoint `api/subscribe.ts` was vulnerable to HTML Injection because it embedded the user-provided `email` directly into the HTML of the outgoing email without escaping. Additionally, it leaked internal server error messages to the client and trusted the `Host` header for generating the logo URL (Host Header Injection).
**Learning:** Even when sending emails, user input must be sanitized. Email clients render HTML, making them susceptible to injection attacks. Trusting user-provided headers like `Host` can lead to SSRF or phishing vectors in emails. Finally, exposing `error.message` to the client violates the "fail securely" principle.
**Prevention:** Always escape user input before embedding it in HTML. Never trust the `Host` header for constructing URLs sent in emails. Generic error messages should be returned for 500 errors.
## 2026-07-25 - Vercel API Unhandled Exceptions & DoS
**Vulnerability:** The Vercel Serverless function `api/subscribe.ts` lacked validation for the existence and type of `req.body`, as well as missing size limits for the `email` string. This could lead to a 500 Server Crash (if `req.body` is undefined during destructuring) and Potential Denial of Service (DoS) due to resource exhaustion when processing excessively large strings through the regex-based HTML escape function.
**Learning:** Vercel functions receive raw objects. Never assume `req.body` exists or contains expected structures. Always use `typeof` checks before destructuring and enforce strict size limits on user-provided strings before any processing (especially regexes) to maintain reliability and security.
**Prevention:** Implement strict type and size boundary checks (e.g., `typeof req.body === 'object'`, `email.length <= 254`) on all user inputs at the absolute beginning of API endpoints.
