## 2024-06-29 - Email HTML Injection & Info Leakage
**Vulnerability:** The API endpoint `api/subscribe.ts` was vulnerable to HTML Injection because it embedded the user-provided `email` directly into the HTML of the outgoing email without escaping. Additionally, it leaked internal server error messages to the client and trusted the `Host` header for generating the logo URL (Host Header Injection).
**Learning:** Even when sending emails, user input must be sanitized. Email clients render HTML, making them susceptible to injection attacks. Trusting user-provided headers like `Host` can lead to SSRF or phishing vectors in emails. Finally, exposing `error.message` to the client violates the "fail securely" principle.
**Prevention:** Always escape user input before embedding it in HTML. Never trust the `Host` header for constructing URLs sent in emails. Generic error messages should be returned for 500 errors.
## 2026-07-26 - Missing Input Validation on Vercel Functions
**Vulnerability:** API endpoints (like `api/subscribe.ts`) lacked basic validation for the existence and type of `req.body` and its fields before destructuring or calling methods (e.g., `.includes()`). This could lead to unhandled `TypeError` exceptions if an attacker sends an empty payload or a payload with unexpected data types, resulting in a Server Crash or 500 error (Application-level DoS).
**Learning:** Vercel serverless functions pass raw objects for the request body depending on content-type and configuration. Never assume the shape or type of incoming data is correct, even for simple fields. Unhandled exceptions in endpoints can degrade service availability.
**Prevention:** Always validate that `req.body` exists and is of the expected type before destructuring. Ensure specific fields (like `email`) are strings (or their expected type) before invoking methods on them.
